# B7: No dead-letter handling for bad messages

- **Switched on by:** `payments.bad-messages: retry-forever`. The bug-free value is `dead-letter`.
- **Scan pattern:** P7, flagged at its location.
- **Code:** [TopicConfig.java](../../demo-app/src/main/java/dev/faultline/demo/payment/TopicConfig.java)
- **Plan:** [b7.plan.yaml](../../benchmark/b7.plan.yaml)

## The bug

A message whose listener keeps throwing is retried forever:

```java
return new DefaultErrorHandler(new FixedBackOff(500, FixedBackOff.UNLIMITED_ATTEMPTS));
```

One message that can never succeed blocks every message behind it on its partition.

## How Faultline proves it

The API publishes to `payments.raw`, and Faultline's relay forwards it to `payments.requested`, corrupting the
300th message once. 2,000 payments.

The check that fails is `no-lost`.

## Evidence

| Run | Fault fired | What the check found |
|---|---|---|
| run-1 | 1 of 1 corrupted | 752 payments stuck behind it |
| run-2 | 1 of 1 corrupted | 752 payments stuck behind it |
| baseline | none | every payment applied |

Confirmed: the check failed in 2 of 2 runs with the fault, and passed in the baseline. On the bug-free build, the same plan came out suspected: the fault fired in both runs and every check passed.

## The fix

After 2 more tries, park the message on a dead-letter topic (`payments.bad-messages: dead-letter`), and the
partition moves on:

```java
new DefaultErrorHandler(new DeadLetterPublishingRecoverer(kafka), new FixedBackOff(0, 2));
```

Only the corrupted message is missing then, and the checks excuse it.

Rerun: `./faultline benchmark --bug B7`
