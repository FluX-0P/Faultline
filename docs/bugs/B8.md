# B8: Saves, then publishes "payment completed"

- **Switched on by:** `payments.completed-events: after-commit`. The bug-free value is `outbox`.
- **Scan pattern:** P8, flagged at its location.
- **Code:** [CompletedEvents.java](../../demo-app/src/main/java/dev/faultline/demo/payment/CompletedEvents.java)
- **Plan:** [b8.plan.yaml](../../benchmark/b8.plan.yaml)

## The bug

The worker saves the payment, then publishes `payment completed` once it has committed:

```java
@TransactionalEventListener
void onCommitted(PaymentCompleted event) {
    publish(event.accountId(), json.writeValueAsString(event));
}
```

A crash in between loses the event. Kafka delivers the message again, but the payment is already done, so nothing
publishes the event again.

## How Faultline proves it

Crash worker-1 just before `CompletedEvents#publish` publishes, on every 100th event, twice; 3,000 payments.

The check that fails is `no-lost-downstream`.

## Evidence

| Run | Fault fired | What the check found |
|---|---|---|
| run-1 | 2 of 2 crashes, 2 restarts | 2 payments applied with no event on payments.completed: pay-42-189, -1193 |
| run-2 | 2 of 2 crashes, 2 restarts | the same two |
| baseline | none | an event for every payment |

Confirmed: the check failed in 2 of 2 runs with the fault, and passed in the baseline. On the bug-free build, the same plan came out suspected: the fault fired in both runs and every check passed.

## The fix

A transactional outbox (`payments.completed-events: outbox`). The event is saved with the payment, so it exists
only if the payment does. A relay on every worker publishes it, after a crash too.

Rerun: `./faultline benchmark --bug B8`
