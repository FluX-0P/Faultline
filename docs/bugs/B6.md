# B6: Immediate, unlimited retries

- **Switched on by:** `payments.provider.retry: immediately`. The bug-free value is `with-backoff`.
- **Scan pattern:** P6, flagged at its location.
- **Code:** [ProviderClient.java](../../demo-app/src/main/java/dev/faultline/demo/payment/ProviderClient.java)
- **Plan:** [b6.plan.yaml](../../benchmark/b6.plan.yaml)

## The bug

A failed charge is tried again at once, as often as it takes:

```java
} catch (ResourceAccessException | HttpServerErrorException e) {
    if (backoff) pause(attempt);   // without it: again, at once, forever
}
```

A provider coming back from an outage is buried under the retries of every worker.

## How Faultline proves it

Take the fake provider down 5s into the traffic, for 6s. Like a real service coming back, it then stays down
while it gets more than 50 requests a second. 2,000 payments.

The check that fails is `recovery-within`.

## Evidence

| Run | Fault fired | What the check found |
|---|---|---|
| run-1 | the outage, once | 1,500 payments never applied: the provider stayed down |
| run-2 | the outage, once | the same |
| baseline | none | every payment applied |

Confirmed: the check failed in 2 of 2 runs with the fault, and passed in the baseline. On the bug-free build, the same plan came out suspected: the fault fired in both runs and every check passed.

## The fix

Back off (`payments.provider.retry: with-backoff`): 100ms, doubling up to 1s, with jitter. The workers retry a few
times a second, the provider is back as soon as the outage ends, and the backlog drains in seconds.

Rerun: `./faultline benchmark --bug B6`
